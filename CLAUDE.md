# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Personal wedding photo album ("Schrikkeldag 2020 - Hans en Marijke"), built with Next.js + TypeScript + Panda CSS. Deployed via Vercel; a `netlify.toml` also exists for static-export deploys to `out/`.

## Commands

The project uses **pnpm** (see `pnpm-lock.yaml`). Node `>=18`.

- `pnpm dev` — start the Next.js dev server.
- `pnpm build` — production build (also runs Panda extraction + TypeScript type-check).
- `pnpm start` — serve the production build.
- `pnpm prepare` — runs `panda codegen` (called automatically on `pnpm install`). Re-run manually if you change `panda.config.ts`.
- `pnpm trouble` — nuke `node_modules` + lockfile, run `ncu -u`, reinstall. Use only when dependency state is broken; this bumps every package and can introduce churn.

There are no separate lint/test scripts. `tsc --noEmit` runs as part of `next build`.

## Architecture

### Pages Router + getServerSideProps

This app uses the **Next.js Pages Router** (not App Router). Data-fetching/auth uses `getServerSideProps`. Don't introduce App Router conventions without converting the rest of the app.

- `pages/_app.tsx` — imports `styles/globals.css` (Panda's `@layer` directives — actual rules are injected at build time by the PostCSS plugin) and initializes Google Tag Manager (`GTM-KZ7Z257`) from a `useEffect`. No theme provider — Panda is build-time and theme tokens are CSS variables.
- `pages/_document.tsx` — minimal: just sets `<html lang="nl">`. No SSR sheet collection (Panda is build-time, no runtime CSS-in-JS).
- `next.config.js` — only sets `reactStrictMode`. No SWC styled-components transform needed.

### TypeScript

- `tsconfig.json` is `strict: true` with `noUncheckedIndexedAccess`. `jsx` is `react-jsx`; `noEmit` (Next does the actual transform via SWC).
- `types/react-photo-gallery.d.ts` is a hand-written ambient module — the library is unmaintained and ships no types. Update it if you start using more of its API.
- `components/GalleryLightbox/types.ts` exports the shared `Photo` interface used by the gallery, grid item, and lightbox header.

### Styling (Panda CSS, recipe-based)

- `panda.config.ts` defines named **recipes** (one per visual component) under `theme.extend.recipes`. Each recipe sets a stable `className` (e.g. `'gallery'`, `'grid-image'`, `'lightbox-header'`) so the rendered HTML has one semantic class per element, not Panda's default atomic class soup. Tokens for color/font/radius/shadow live alongside the recipes; semantic tokens like `lightbox.bg` precompute alpha values that used to be runtime `Color()` calls.
- `globalCss` in `panda.config.ts` carries the body baseline + the `@font-face` for the embedded SwitzeraADF base64 woff.
- `styled-system/` is generated by `panda codegen` (gitignored). Components import recipes from `styled-system/recipes`, e.g. `import { gridImage } from '../styled-system/recipes'` then `<div className={gridImage()} />`. Adding a new visual component = adding another recipe to the config + importing it in the component.
- `postcss.config.cjs` wires the `@pandacss/dev/postcss` plugin into Next's pipeline so `styles/globals.css` (the `@layer reset, base, tokens, recipes, utilities;` directive) is hydrated with the actual extracted CSS at build time.
- `pnpm dev` and `pnpm build` both prefix `panda codegen &&` so a fresh checkout type-checks before install.

### Authentication flow (cookie-based, GitHub-backed)

The "login" is a quirky GitHub-API-as-password mechanism — keep this in mind before "fixing" it:

1. `pages/login.tsx` posts a `username` (input is `type="password"` for UX/a11y but the field semantically holds a GitHub username) to `pages/api/login.ts`.
2. `pages/api/login.ts` hits `https://api.github.com/users/<username>` and returns the numeric GitHub user `id` as the `token`. All failure modes (missing username, non-existent user, network error) collapse into a single `401 'Wachtwoord onjuist'` response so the endpoint can't be used to enumerate GitHub users.
3. `utils/auth.tsx#login` stores the token in a `token` cookie (1-day expiry) via `js-cookie` and pushes to `/album`.
4. `pages/album.tsx` validates the cookie in `getServerSideProps` by calling `verifyToken()` from `utils/verify-token.ts` directly (no HTTP self-fetch) and redirects to `/login` on failure. The component additionally calls `useLogoutSync()` from `utils/auth.tsx` to follow logout events from other tabs via `localStorage.logout` + `storage` event.
5. `pages/api/album.ts` re-validates via the same `verifyToken()` util — kept so client-side checks still work, with `Cache-Control: private, max-age=300` to avoid hitting GitHub on every request.

### Gallery rendering

`components/GalleryLightbox/index.tsx` is the heart of the app. It's a function component with hooks. It composes:

- `react-photo-gallery` for masonry layout (custom `GridImage` renderer; CSS-grid override applied via the `gallery` recipe so the library's inline `height: <px>` is overridden with `height: unset!`). The library is unmaintained — peer-deps say React 16, but it works in React 19 at runtime.
- `next/image` with `fill` mode inside `GridImage` — automatic AVIF/WebP, responsive `srcset`, and built-in lazy loading. `unoptimized` is set for `.gif` files so animated GIFs keep playing.
- `react-spring-lightbox` for the fullscreen viewer, with custom `LightboxHeader` and `LightboxArrowButton` components.
- Client-only mount guard: `Gallery` is only rendered after `useEffect` sets `clientSide: true`, to avoid SSR layout mismatch.
- `columnConfig` sets responsive column counts based on container width (1/2/3/4 cols at 0/500/900/1500 px).

`GridImage` is a focusable button (`role="button"`, `tabIndex={0}`, Enter/Space → click) so the gallery is keyboard-accessible.

`pages/album.tsx` iterates `data.photos` from `data/data.json` and renders one `GalleryLightbox` per group (each group has its own `title` and `photos[]`). The `Photo` type lives in `components/GalleryLightbox/types.ts`. Each photo entry has `src` (relative to `/public/`, e.g. `images/foo.jpg`), `caption`, `alt`, `className` (`vertical`/`square`/`horizontal`), `width`, `height`. The `width`/`height` in the data are placeholders (`1, 1`) — the visual layout comes from CSS grid, not the library's masonry calc. `src` paths get a leading `/` prepended at the call sites since they're root-relative under `public/`.

### Image assets

- `public/images/` — checked-in gallery images.
- `public/images-800/` and `public/images-orig/` — git-ignored (resized variants / originals are kept locally only).

### Theming

Theme tokens live in `panda.config.ts` (`theme.extend.tokens.colors` and `theme.extend.semanticTokens.colors`). The accent/link color is `#ff0099` (hot pink, token `link`) on a tiled mint background (`tile.png`, token `pageBg`). When adding new components, reference tokens by name (`color: 'link'`) rather than hardcoding hex values — this keeps everything in sync with `panda.config.ts`.
